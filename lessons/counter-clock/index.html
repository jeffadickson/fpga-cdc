What the counter clock actually sees

The bus is a 4-bit count from another domain. Each bit switches at its own time, and a bit can toggle several times before it settles. The counter's clock samples every bit at each rising edge and reads whatever 0 or 1 is there at that instant.

Across 4,000 runs

A run places the transition at a random point relative to the clock, draws each bit's skew, and adds toggles where bounce is on. "Jump" means a clock edge read a value that is neither the old count nor the new one.

Reading it

Each column is one rising clock edge. The four 0/1 values in that column are what the counter sees at that instant. When an edge lands while bits are still moving, some bits have already switched and others have not, so the column combines old and new bits. With multiple toggles, a bit can read 1, 0, 1 across successive edges, so the same count can appear several times with different values.

With Gray code and one clean switch per bit, the only values a column can show are the old count and the new count, so there is no jump. Toggle the multiple-toggle option on and Gray code still jumps: a glitch on a bit that should not change, or a bit that toggles three times, can produce a code that is not adjacent to the old one. Gray code limits the damage; it does not remove the need for a synchronizer.
